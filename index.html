Deep Dive · Independent Project, 2026

Alzheimer's Market Overview: Dual-Platform Dashboards

Problem

A 202,499-row TRx pharmaceutical dataset had real signal in it, brand share shifting, specialty channels performing differently, but no single dashboard the whole stakeholder audience actually trusted.

Why

A brand manager who lives in Tableau and an analyst who lives in Python shouldn't have to fight over which tool the truth lives in. The finding matters more than the tool it's rendered in.

How

The same brand/specialty/channel analysis, built twice: once as an interactive Python (Plotly) dashboard exported as a shareable standalone HTML file, once as a native Tableau workbook, so either audience gets the same answer in the tool they already trust.

202,499rows analyzed across brand, specialty, channel
2parallel dashboards built (Python + Tableau)
3dimensions compared (brand, specialty, channel)
1standalone shareable HTML export, no server needed

This is where principle 04 (build for the audience, not just the tool) isn't an abstraction: the same brand/specialty/channel analysis ships twice, once in Tableau for stakeholders who live there, once in Python for anyone who wants to dig into the code.

Deep Dive · Pennsylvania State University, 2026

Penn State Alumni Event Forecasting

Problem

Six years of alumni event data lived in 6 disparate Excel files with no shared KPI definitions, so planning for the next event meant starting from scratch and guessing at the budget.

Why

A budget conversation without a range is just a guess dressed up as a number. Stakeholders needed to see best-case and worst-case, not one point estimate to argue about.

How

Consolidated 6 Excel sources into one unified KPI model, then built a blended trend + recency-weighted forecast with three funding scenarios, conservative, expected, optimistic, so planning moved from reactive to data-informed.
